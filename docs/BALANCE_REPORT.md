# Balance simulation report

Generated by `tools/simulate_balance.gd` (Godot 4.7.2, headless).

```
godot --headless --path <project> res://tools/SimulateBalance.tscn
```

Seed `20261020`, tick `0.2 s`, waves `1-50`, runs `8`. Every number is read from
`data/*.tres` and every formula from `WaveRules`; nothing is duplicated here.

## Model and assumptions

- The Tree sits at the arena centre; the archer range is measured from it.
- Enemies walk from `640 px` to the Tree surface (`90 px` + body radius).
- Path length is inflated by a constant `15%` for steering and separation.
- All archer and tower damage focuses the nearest enemy, matching the
  default `nearest` targeting; overkill is wasted like it is in game.
- Towers are assumed to have the whole path inside their range (pads sit
  at `300 px`, the shortest tower range is `380 px`, the path spans
  `90-640 px`), so their DPS applies while a target is in range.
- Procedural spawns use the expected `55/30/15` Grunt/Runner/Brute mix.
- Only the lead enemy is slowed by Frost Spires.
- Bosses summon `4` Runners at `70%` and `40%` HP and enrage at `30%`
  (`WaveRules.boss_hp` and `WaveRules.boss_wave_entries`).
- Waves 1-`authored_max` are authored and get no wave multiplier; the
  `1.16`/`1.02`/`1.06` curves start at wave `authored_max + 1`.
- Between runs all Gold is spent cheapest-first on the eight meta tracks.
- Cards, ads, revives and the wave-30 Gem milestone do not affect power.
- Two spending profiles are simulated because the split matters: a
  tower costs `60` Coins for `14` DPS (about `0.23` DPS/Coin) while the
  first Canopy Bows level costs `80` for about `4.5` DPS (`0.06`).

## Reading the report

- `DPS` is the archer + tower damage per second against zero armor at the
  start of the wave; armored waves clear slower than `total HP / DPS`.
- `Coins` is the wave payout (kills + `10 + 2*wave`) and excludes the
  starting balance and earlier waves.
- `Wave reached` counts the wave the run died in; `Waves cleared` does not.
- A wave only ends when the last enemy dies, so leaked enemies keep
  hitting the Tree and inflate the clear time.

## Tuning notes

- One formula changed. `WaveRules.scaling_for_wave()` now starts the
  `1.16` / `1.02` / `1.06` curves at wave `authored_max + 1` instead of at
  wave 1. Before the fix, authored waves 1-10 ran at x1.0 and wave 11
  jumped to `1.16^10` (~4.4x) with no matching growth in player power.
- No `.tres` value was changed by this pass.
- Finding 1 - wave 8 is the first wall. Both profiles lose runs there
  while player DPS is still 56-115; the authored spike (19 enemies,
  `swift`, first wave modifier) arrives before the economy can answer it.
- Finding 2 - the curve flattens after wave 10. Once a run passes wave 8
  it usually reaches wave 20-37, because procedural waves 11-19 have less
  total HP than the authored wave 9 (e.g. `1.16^1` vs 32 enemies at
  `swarm`), so the same DPS clears them faster.
- Finding 3 - Gold is winner-take-all. A run that dies at wave 8 pays 112
  Gold; a run that passes it pays 1 600-2 000, which buys most of the
  cheap meta tracks at once. The measured jump from `wave 8` (runs 1-5)
  to `wave 37` (run 6) is that step, not a smooth progression.
- Finding 4 - strategy spread. `0.23 DPS/Coin` for an Archer Tower versus
  `0.06` for the first Canopy Bows level makes tower-first play worth
  roughly two extra waves on run 1 and ten on later runs.
- Recommendation (not applied - this stage is bug-fix only): raise the
  early upgrade efficiency or the tower price, soften the wave 8-9
  authored spike, and re-run this scene before any store build.
